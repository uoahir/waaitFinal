## 💡 &nbsp; WAAIT 그룹웨어
WAAIT은 " WE ARE ALL IN THIS TOGETHER "의 약자로 함께하는 협업의 힘을 상징합니다. <br>
WAAIT은 IT 기업이 사용하는 그룹웨어로 다양한 팀이 더욱 원활하게 소통하고 효율적으로 협업할 수 있도록 설계되었습니다. <br>
직관적이고 사용이 간편한 인터페이스를 통해 직원들이 서로의 업무를 쉽게 공유하고 조율할 수 있습니다. <br>

## 💡 &nbsp;프로젝트 주요 기능
- 로그인 : Spring Security 를 이용한 로그인 기능, 로그인 계정 별 권한에 따른 페이지 접근 제한 기능
- 메인페이지 : 출퇴근 기능, 채팅/메일 연결 기능, 조직도
- 사내메일 : 메일작성, 보낸메일함, 받은메일함, 휴지통
- 채팅기능 : Web Socket 을 이용한 채팅 기능
- 코드리뷰 기능 : 자신의 코드를 올리면 팀원들이 코드리뷰해주는 기능
- 부서관리 기능 : 팀 등록, 수정, 삭제 기능
- 프로젝트 관리 기능 : 프로젝트에 투입될 직원을 선택하여 프로젝트를 생성하는 기능, 프로젝트 진행상태를 확인할 수 있는 기능
- 일정관리 기능 : 캘린더에 개인 일정 및 부서 일정 등록, 수정, 삭제 기능
- 전자결재 기능 : 기본보고서 등 문서작성 및 상신 기능, 결재선 지정 기능, 문서 회수 기능, 문서 반려 및 승인 기능

## 💡 &nbsp;담당 : 전자결재 테이블 설계, 전자결재 기능 구현
https://github.com/user-attachments/assets/1c463307-7930-4d36-824e-1282f92e984e

### 구현한 기능
1. 문서 작성(파일 업로드) 및 결재선 지정(추가, 삭제, 변경) 기능
2. 문서 상신 시, 진행 중인 문서함에서 문서의 현재 상태 확인 가능
3. 문서가 상신 상태일 때만 해당 문서 회수가능
4. 문서 결재 및 반려
5. 문서 유지 관리 및 만료처리

### 추상화
전자결재 시스템의 다양한 문서 유형에 대해 공통적이고 필수적인 데이터를 관리하기 위해, 이를 추상 클래스(AbstractDocument)로 설계하여 중복을 줄이고 유지보수를 용이하게 했습니다. 추상 클래스는 공통 데이터 필드를 포함하며, 각 문서 유형이 필요한 필드를 상속하여 특정 기능을 구현할 수 있습니다.<br>
AbstractDocument: 문서 ID, 생성일자, 작성자 등의 공통 필드와 승인 상태<br>
문서 구조를 추상화하여 설계함으로써 새로운 문서 유형을 추가하거나 수정할 때 코드의 일관성을 유지하고, 시스템의 유연성을 높였습니다.

### Spring Quartz를 활용한 문서삭제 기능
보존 연한 기능을 추가하기 위해, 해당 문서의 만료일에 문서를 삭제하는 로직을 구현했습니다.
이를 위해 스케줄링 기능을 제공하는 여러 라이브러리 중 어떤 것을 선택할지 고민해본 결과, Spring Scheduler, Spring Batch, Spring Quartz의 세 가지 옵션을 고려하였습니다.

1. Spring Scheduler
개요: Spring의 기본 스케줄링 기능으로, @Scheduled 어노테이션을 통해 간단한 주기적인 작업을 설정할 수 있습니다.
장점:
설정이 간단하고 코드가 깔끔함.
가벼운 작업에 적합하여 작은 프로젝트에 유리.
단점:
복잡한 작업 흐름이나 배치 처리가 필요한 경우 기능이 제한적임.
스케줄링된 작업의 실패에 대한 복구 기능이 부족함.

2. Spring Batch
개요: 대량의 데이터를 일괄 처리하기 위한 프레임워크로, 배치 작업을 설정하고 관리하는 데 최적화되어 있습니다.
장점:
대량 데이터 처리와 작업의 재처리, 트랜잭션 관리가 용이함.
처리 흐름을 구성하기 위한 다양한 구성 요소(읽기, 처리, 쓰기)가 제공됨.
단점:
설정이 상대적으로 복잡하고, 배치 작업에 대한 이해가 필요함.
경량 스케줄링에는 과한 기능이 될 수 있음.

3. Spring Quartz
개요: 강력한 스케줄링 라이브러리로, 복잡한 스케줄링 요구사항을 처리할 수 있는 다양한 기능을 제공합니다.
장점:
Cron 표현식을 사용하여 복잡한 스케줄을 설정할 수 있음.
트리거, 잡, 리스너 등의 구성 요소를 활용하여 유연하게 작업을 관리할 수 있음.
단점:
설정과 관리가 상대적으로 복잡함.
오버헤드가 발생할 수 있어 가벼운 작업에는 불필요할 수 있음.

결론 : 
각 라이브러리는 특정 요구사항에 따라 장단점이 있으므로, 프로젝트의 성격에 맞는 라이브러리를 선택하는 것이 중요합니다. 
따라서, 특정 요일이나 시간에 작업을 실행하도록 설정할 수 있는 Spring Quartz를 선택해, JOB 과 TRIGGER 이용하여 로직을 구성하였습니다.

### CSS 와 JavaScript 파일 분리의 중요성
프로젝트 이후, jsp 화면에서 CSS 와 JavaScript 를 수정할 때, 유지보수가 어렵다는 것을 느꼈습니다. 이후 프로젝트를 업그레이드 하면서 가독성을 높이기 위해 CSS와 JS 파일을 분리할 예정입니다.
이를 통해 코드의 재사용성을 높이고, 변경 사항을 쉽게 관리할 수 있을 것입니다.

### RESTful API 활용
프로젝트 초반에는 JSP(HTML)로 응답 데이터를 전송했지만, 이후 JSON 형태의 데이터를 전송하여 클라이언트 측에서 해당 데이터를 처리하고 렌더링할 수 있게 하였습니다. 
RESTful API를 활용해 좀 더 일관적이고 효율적인 데이터 전송을 구현할 수 있습니다. 이를 통해 클라이언트와 서버 간의 역할을 명확히 하고, 프론트엔드와 백엔드의 분리를 강화할 수 있었습니다.

### 컴포넌트화 작업의 필요성
프로젝트를 다시 확인하며, 공통적인 부분들은 컴포넌트화했으면 좋았을 거라는 생각을 했습니다.
컴포넌트화해서 같이 사용할 수 있도록 만들면, 해당 프로젝트를 조금 더 효율적으로 만들 수 있을 거라고 생각했습니다.
- 재사용성 : 한 번 만든 컴포넌트를 여러 곳에서 재사용할 수 있어서 코드의 중복을 줄일 수 있습니다.
- 유지보수 용이성 : 컴포넌트 단위로 수정이 가능하므로 특정 기능에 문제가 생겼을 때 해당 컴포넌트만 점검하고 수정하면 됩니다.
- 협업 용이성 : 팀원들이 서로 다른 컴포넌트를 동시에 개발할 수 있어 협업이 원활해집니다.
이러한 이유로, 향후 프로젝트에서는 공통적인 부분을 컴포넌트화하여 효율성을 극대화하고 코드의 가독성과 유지보수성을 높이기 위해 노력할 것입니다.

### 향후 계획 
1. 실시간 알림 시스템 개선 : Websocket 을 활용한 실시간 알림기능 보완
2. 보안강화 : JWT와 OAuth2.0 을 통해 인증시스템 보완
3. 실제배포
